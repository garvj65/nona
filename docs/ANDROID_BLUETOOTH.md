# Android Bluetooth preview — 0.6.1

This native Android app implements direct Bluetooth **keyboard + mouse** input. The Windows NONA server does not need to run for this mode. No IP address, shared Wi-Fi or CA certificate is used for the Bluetooth control connection. This is an installable test build, not a Google Play release or an Xbox/PS5 controller implementation. Compatibility with the owner's Vivo radio and actual games is a physical acceptance test.

## Get the test app

Open the repository's **Actions → Android preview**, choose a successful build and download **nona-android-preview** from its Artifacts section. Unzip it and copy `app-debug.apk` to the phone. Open the APK and allow installation from that specific download/file app if Android requests it. You do not need developer mode or USB debugging for a normal APK installation. The test artifact requires GitHub access and is retained for 30 days.

This is a debug-signed preview. Its signing key is generated by the CI environment and is not a managed release key; a later test build may require uninstalling the old preview first. App settings will be removed by uninstall. Production distribution needs managed release signing and store review. No signing private key is committed to the repository.

## Pair and connect

1. Close the existing NONA server on Windows for this test. Keep laptop Bluetooth enabled. The game may still need its own internet connection.
2. Open NONA on Android. Allow **Nearby devices** when asked. The app requests connection permission first, and discoverability permission only when pairing a new computer. It requests no location or internet permission.
3. Tap **Set up Bluetooth** if needed. Wait until the app offers paired devices. Starting registration is not treated as a successful HID connection. Unsupported/failed registration is shown with retry/help rather than an invented connected state.
4. Tap **Pair a new computer**, approve Android's discoverability prompt, then on Windows open Bluetooth settings → Add device → Bluetooth and select the phone. Confirm the OS pairing prompt. Use the phone's actual Bluetooth name; NONA does not globally rename it.
5. Return to NONA. If Windows connects within about two minutes of the discoverability prompt, NONA adopts that computer automatically. Otherwise select the Windows computer from **Paired devices**. This list can contain other paired Classic Bluetooth devices; choose the PC, not headphones. The app will only send input to the selected bonded host. An ordinary Bluetooth bond is not the same as a connected HID session.
6. After the app reports **Connected**, tap **Open controller**. Choose **Move & look** or **Racing**. Open/focus your game on the PC, then tap **Play** on the phone. Inputs begin neutral and paused until that action.

If the computer is absent, finish Windows pairing while the phone is discoverable and return to NONA. If HID registration or connection fails, use **Connection details** and copy the report with the phone model, Android version and current stage. Bluetooth setup and connection attempts have bounded waits and can be retried. An app/phone exposing the public API is not proof that its Bluetooth stack supports this role successfully.

## Controls

- **Move & look:** touch and drag the left area for 8-way WASD movement (equal 45° sectors, so a slightly angled thumb still walks straight); swipe the right area for relative mouse look; Jump = Space, Run = Shift, Use = E, Action = Q.
- **Racing:** the left area supplies Left/Right; Gas = Up, Brake = Down, Slide = Space, Boost = Shift. Steering is **proportional by default**: part lock pulses the arrow key (100 ms cycle, key-down time grows with stick distance), full lock holds it. Games that act once per key press, such as lane switchers, need this off in **Controls**. Continue using the Wi-Fi racing mode for the already-tested position-based tilt steering.
- **Controls:** adjust camera speed, right-button dragging for third-person cameras, and optional gyro assistance while touching the look area. Disable right-button dragging for first-person games that capture the mouse themselves. Gyro assistance is for Move & look; it is unavailable if the phone has no gyroscope.
- **Stop:** clears held keys, modifiers and mouse buttons. Re-entering the controller, changing its orientation/profile, cancelling touch, locking/backgrounding the app, or losing the connection pauses input. Resuming requires Play; old held input is not replayed.

Direct HID acts like a physical keyboard/mouse. There is no PC companion watching which application is focused. **Stop before switching Windows applications.** While connected, NONA runs a small foreground service ("NONA is connected" notification) so Android keeps its Bluetooth input registration through a screen lock or another app. Input still pauses the moment NONA leaves the screen; the computer only sees a keyboard with nothing pressed. Return and tap **Play**; you do not need to reselect the computer. After ten minutes off-screen NONA releases the computer completely. On the next launch it reconnects to the last computer you chose unless you tapped **Disconnect**. The app attempts neutral reports before disconnect/unregister, but abrupt phone loss and the Windows Bluetooth stack's cleanup need physical testing.

## First physical acceptance test

1. With no NONA PC process running, open Notepad on Windows. Move the phone stick and tap Jump: keyboard input should arrive. Stop and check that no key remains held.
2. Test right swipe/camera and right-button release in a suitable app/game. Then test the same Roblox experience that previously felt restricted. First confirm it runs smoothly using the laptop's own keyboard/mouse.
3. Check simultaneous move/look/jump; keyboard movement remains digital. Record the exact experience URL, direction/speed, sensor availability and feel. A connected Bluetooth icon alone is not a gameplay pass.
4. Explicitly test Stop, phone lock/background, Bluetooth off/out-of-range, reconnect and orientation change. Verify there are no stuck inputs and no automatic resumption. The physical lock/loss checks from the Wi-Fi prototype are still open too.

No real Bluetooth/gameplay success is claimed by the APK build, unit tests or emulator. The emulator UI tests use a **debug-only, in-process preview adapter** with no radio/OS input. External intents cannot turn on that adapter; the release source set only constructs the actual Bluetooth link.

## Build and validation

Open `android/` in Android Studio with Android SDK 35 and JDK 17, or run its checked-in Gradle wrapper:

```powershell
cd android
.\gradlew.bat testDebugUnitTest lintDebug assembleDebug
```

The Gradle 8.11.1 distribution is SHA-256 pinned. The wrapper JAR was obtained from the official Gradle v8.11.1 repository and matches the published checksum `2db75c40782f5e8ba1fc278a5574bab070adccb2d21ca5a6e5ed840888448046`. CI also validates wrappers. The native project has pure report/session tests, Android lint, debug/release compilation and an emulator UI/lifecycle test; see the actual Actions run for pass/fail evidence.

The companion Wi-Fi browser controller remains available. Native QR/TLS companion pairing, a packaged Windows installer, generic HID gamepad/XInput support, release signing and Play Store distribution remain separate work. See APP_PAIRING.md and BLUETOOTH_AND_DEPLOYMENT.md.
